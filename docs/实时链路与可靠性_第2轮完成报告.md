## 12. 已知限制与遗留风险

1. **端到端 p95 主要构成仍是逐条 ACK 的 stop-and-wait**（第 1 轮已声明）：本轮 outbox 写盘再叠加 ~1.7ms/条边际（4.18% 预算）。若要 <50ms 需改滑动窗口 ACK —— 属协议语义变更，第 3 轮。
2. **地面跨重启去重仍是"读磁盘文件比 sha"**，无持久化 sha 索引：大 run 下每条重传都要读盘（尽力而为 + fail-closed，第 1 轮限制 2 延续）。
3. `LosslessProcessingQueue` 硬上限阻塞默认 30s 极限（消费者完全卡死时 USB 线程最长阻塞至该上限后 fail-closed 存 `failed_item`）：极端卡死场景的优雅路径仍依赖 fatal/排空失败上报，未另行设计（第 1 轮限制 3 延续）。
4. **本机 Qt 6.11.2 环境预算**：单进程 discover 不可用（§9.5），全量必须走 `docs/run_tests_batched.py`；`PASS*` 豁免只覆盖"测试全绿后的解释器拆除崩溃"。bench 端到端 p95 在本机存在 526ms 级漂移记录，绝对延迟结论需指定硬件。
5. 常驻服务的"待命期"仍持有 USB：若用户在待命期物理拔线，`holds_usb` 判据会持续拒绝手动 USB 入口直到 `shutdown()`/下一次操作触发 FAULTED —— 已可观测（`last_stop_reason`/statistics），但真机手感未验证。
6. 校准 `activate` 后新校准作用于后续采集已验证（trace 级证据），但**不追溯**已保存数据；校准与会话的 profile 身份目前经 `calibration_id` 关联，尚无跨进程持久化校验。
