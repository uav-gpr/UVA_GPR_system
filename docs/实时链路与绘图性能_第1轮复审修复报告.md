## 2. 每个复审问题：根因 / 修改位置 / 测试

### 一、RemoteSender 真实排空语义

**根因**：`stop(drain=True)` 用 `queue.empty() and not _busy` 判断完成——
"已从 queue 取出、处于 pending 重试"的消息不在计数内（`_run` 的局部变量
`pending`），断网时 drain 误判完成后仍强制 `_stop` 丢弃内容；状态消息也
从不计入。

**修改**（`uav_gpr_qt.py` RemoteSender）：
- 新增 `_outstanding` 计数（`_note_enqueued`/`_note_completed`，
  `outstanding_count()`）：入队 +1；trace 收到匹配 ack_trace −1；状态消息
  send_remote_frame 成功 −1。覆盖 queue 内、in-flight、pending 重试三种形态。
- `stop(drain=True)`：等待 `outstanding==0`；超时**返回 False 且什么都不动**
  （不置 `_stop、不插退出哨兵、不关 socket/线程；pending 与队列保留，
  再次调用可继续排空）。只有 drain=False 才强制停止并明确放弃。
- `_run` 维护 `self._pending_item`（pending 重试项可观测）。

**测试**（`tests/test_round1_review_fixes.py::RemoteSenderDrainTests` +
`MainWindowCloseDrainTests`）：
- `test_offline_drain_timeout_keeps_thread_and_data`：断网+队列非空 →
  stop(drain, 300ms)=False、线程活、`_stop` 未置、outstanding>0；恢复连接后
  继续发送并最终排空（ACK=[1,2]）。
- `test_pending_retry_counted_not_mistaken_as_done`：pending 状态 queue 空
  但 outstanding>0（queue.empty() 不是完成依据）。
- `test_status_message_counts_as_outstanding`：状态消息计入/完成后归零。
- `test_drain_false_forces_stop`。
- `test_close_ignored_when_drain_fails`：closeEvent 排空失败 ignore、成功后
  第二次 accept。

### 二、LosslessProcessingQueue 丢 Trace 路径

**根因**：满队列 put 超时返回 False 后，当前 SelectedSweep 从内存消失但
`_selected_count` 已增加（selected > processed 却可报告 drained）；高水位
每次 put 刷屏。

**修改**（`uav_gpr_qt.py`）：
- put 语义三分：(1) 队列满且未触发硬上限 → 置 `stop_requested` + 回调，
  然后**有界阻塞**等待消费者（触发 Trace 必须入队）；(2) 受控停止后满
  队列 → 立即拒绝（`rejected_after_stop` 计数，调用方不计 selected，绝不
  阻塞 USB）；(3) 阻塞超 `max_wait_s` → fail-closed：item 存入
  `failed_item`（可追踪，绝不静默消失），worker `failed.emit` 并受控停止
  （绝不报告 drained）。
- worker run 循环：`_selected_count` 改为 **put 成功后** 才增加；
  `should_select` 之前先检查 `stop_requested`（受控停止立即阻止后续选择，
  scheduler/selected 口径一致）；put-False 走 fatal（failed_item 路径）或
  受控停止（拒绝路径）。
- 高水位告警只在**跨越阈值**时触发（`prev_depth < threshold <= depth`），
  不再每次 put 刷屏。

**测试**（`tests/test_round1_defaults.py::LosslessQueueTests`）：
- `test_capacity1_paused_consumer_no_silent_loss`：容量1+消费者暂停，
  第二条 Trace 有界等待后入队成功，第三条显式拒绝，全部已入队项处理，
  无 failed_item。
- `test_extreme_block_fail_closed_not_drained`：极端阻塞 → failed_item
  可追踪，绝不报告 drained。
- `test_put_after_controlled_stop_rejected_not_dropped`：受控停止后拒绝
  不丢弃已入队内容。
- `test_high_water_and_hard_limit`：告警只触发一次（跨越语义）。
- worker 级：`test_slow_consumer_lossless_no_drops` /
  `test_trace_index_survives_queue_pressure`（processed==selected 且
  drain_state=drained）；`test_drain_failure_recorded_not_faked`（fatal
  consumer fail-closed 不死锁不伪装）。

### 三、停止状态统一 + 等地面端真正显示完成

**根因**：空中端曾发 `state="drained"`，地面端只识别 `"stopped"`；地面端
收到 command_ack 或状态立即显示"已停止"，未等待 decoder/FIFO 排空。

**修改**：
- `uav_gpr_qt.py`：空中端最终一律 `state="stopped"`（drain_failed 除外），
  排空结果放 `drain_state` 字段。
- `uav_gpr_ground_station.py`：
  - `_on_acquisition_status`：收到 stopped → 记录 `_final_stop_state`，显示
    "正在停止（等待地面显示完成）"，调 `_reconcile_stop_state()`；
    drain_failed 直接显示失败；未知状态显示"未知状态"（**不透出英文
    原始值**）。
  - 新增 `_reconcile_stop_state()`：全部满足才显示"已停止（数据已全部
    排空）"——① 空中端 stopped+drain_state=drained；② decoder queued==0；
    ③ decoder in_flight==0；④ Qt queued 回调已处理（本函数在主线程执行
    即代表已处理到当前时刻）；⑤ display FIFO depth==0；⑥ 最后一条已实际
    提交（FIFO committed 稳定）。在状态到达、显示提交排空两个调用点检查。
  - `send_start`/`send_single` 清 `_final_stop_state`（新任务）。

**测试**（`StopReconcileTests`）：
- `test_final_state_with_busy_decoder_not_stopped`（decoder in-flight→不得停止）
- `test_final_state_with_nonempty_fifo_not_stopped`（FIFO 非空→不得停止）
- `test_auto_stopped_after_last_display_commit`（最后一条提交后自动已停止）
- `test_unknown_state_not_shown_raw`（drained/whatever 不透出原始值）

### 五、地面端跨重启去重

**根因**：trace_index 非法值默认 `int(... or 0)`→落盘 trace_00000；
header sha 被直接信任；磁盘已有文件时不校验内容（重启后同编号不同
payload 会 duplicate-ACK 错误放过）。

**修改**（`ReceiverThread._accept_trace`/`save_trace`）：
- trace_index 严格正整数校验（bool/字符串/0/负数/None/浮点全拒绝，不 ACK
  不落盘）。
- 始终用 payload 计算 `actual_sha` 并校验 header sha256（不信任 header）；
  `_seen_traces` 只记录验证过的 actual_sha。
- 跨重启（内存未命中+磁盘存在）：读磁盘文件 SHA——相同 → duplicate
  ACK；不同 → 冲突拒绝（不 ACK、不覆盖）；读取失败 → fail-closed 不 ACK。

**测试**（`CrossRestartDedupTests`）：
- `test_restart_same_payload_duplicate_ack`（新 Receiver 重传 → duplicate
  ACK、不显示、metadata 一条）
- `test_restart_different_payload_rejected`（拒绝、无 ACK、磁盘原内容）
- `test_invalid_trace_index_and_forged_sha_rejected`（6 种非法 index +
  伪造 SHA；无 trace_00000）
- `test_seen_traces_records_actual_sha`

### 六、地面端关闭顺序

**根因**：closeEvent 先 decoder.stop 后 receiver.stop（顺序颠倒，decoder
停止时 receiver 仍可能产生新任务）；decoder.stop 返回值未检查；FIFO 非空
仍可关闭。

**修改**（`closeEvent` + `GroundTraceDecoder`）：
- 顺序：① receiver.stop + **wait(1500)**（不再产生新解码任务；未退出 →
  ignore）；② decoder.stop(2000) **检查返回值**（排空已有任务后退出；未
  退出 → ignore）；③ decoder queued/in_flight 或 display FIFO 非空 →
  ignore（窗口保留，事件循环继续排空，用户稍后重关）；④ 全部归零才
  accept。绝不 terminate、绝不清空待显示队列。
- `GroundTraceDecoder`：可靠统计（queued/in_flight/completed/rejected，
  `idle` 属性）；stop 排空后退出；异常安全（任何异常不杀死解码线程）。

**测试**（`CloseOrderTests`）：
- `test_decoder_stop_timeout_rejects_close`
- `test_display_fifo_nonempty_rejects_close_then_drains`
- `test_last_trace_during_receiver_stop_still_displayed`（receiver 停止期间
  最后一条仍完成解码+显示）
- `test_no_thread_residual_after_close`（关闭后无 decoder 线程残留）

## 7. 停止状态三队列时序说明

```
用户停止/受控停止
  空中端：生产循环退出 → acquisition_status(stopping) → _shutdown：
    consumer.request_stop → USB 释放 → consumer 排空（processing 队列→0，
    drain_state=drained/drain_failed）→ acquisition_status(stopped,
    drain_state=…) → finished_run
  地面端（每个队列按序归零）：
    ① ReceiverThread 已接收/保存全部 trace（逐条 ack_trace，接收线程
       停止后不再有新任务）
    ② decoder queued→0、in_flight→0（解码完成）
    ③ Qt queued decoded/rejected 回调在主线程处理完（入队 display FIFO）
    ④ display FIFO 逐条提交 → depth→0（最后一条 setImage 完成时
       `_commit_one_display` 触发 `_reconcile_stop_state`）
    ⑤ 全部满足 + 空中 drain_state=drained → 显示"已停止（数据已全部排空）"
    任一不满足 → "正在停止（待解码 N 条 / 待显示 N 条）"；空中
    drain_failed → "排空失败"。
```
