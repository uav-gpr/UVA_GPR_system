## 2. 每个问题：根因 / 代码位置 / 测试

### 一、decoder → Qt 主线程回调屏障

**根因**：GroundTraceDecoder 在 emit Qt 信号**前**就把 in_flight 归零，信号可能
仍在 Qt 事件队列中；`_reconcile_stop_state` 因此提前判定"地面已空闲"。

**修改**（`ground_trace_pipeline.py` GroundTraceDecoder + `uav_gpr_ground_station.py`）：
- 新统计：`submitted / queued / in_flight / in_callback（callback_pending）/
  callback_consumed / decoded_success / rejected`（`statistics()` 全部可见）。
- `in_callback` 在**发出 Qt 信号前** +1（decoded 成功与 rejected 两条路径均占屏障）。
- `_on_trace_decoded`/`_on_trace_rejected`（主线程槽）在 **finally** 中
  `mark_callback_consumed()`；槽内异常被捕获、明确记录到 `decoder.callback_errors`
  并归还计数（不会永久卡住）。
- `_reconcile_stop_state` 检查 `in_callback==0`；不再用"当前正在主线程执行"
  推断其他 queued signal 已处理。
- **停止提交屏障**：最终 stopped 状态到达时记录 `_stop_commit_barrier` =
  此刻 FIFO `total_enqueued`；屏障前的全部 Trace 完成（committed+rejected+failed
  ≥ barrier）才可进入"已停止"。
- decoder rejected>0 或回调异常>0 → 显示"采集状态：地面处理失败（部分 Trace
  解码被拒绝或回调异常）"，**绝不**显示"数据已全部排空"。

**真实 Qt 事件顺序测试**（`CallbackBarrierTests`）：
- `test_stopped_not_shown_until_qt_callbacks_drained`：提交有效 Trace → 等
  decoder 线程完成（**不 processEvents**）→ 断言 `in_callback==1` → 发送
  stopped/drained → **仍显示"正在停止"**；processEvents 完成 B-scan 提交后
  → "已停止（数据已全部排空）"。
- `test_rejected_decoder_blocks_drained_display`：decoder 拒绝 → 显示地面
  处理失败。

### 二、GroundTraceDecoder.stop 幂等

**根因**：线程退出后再次 stop 向无人消费的队列放哨兵 → queued 永久为 1。

**修改**（GroundTraceDecoder.stop/put_job）：
- 幂等：未启动/已退出直接返回 True，**不插哨兵**；
- 同一 stop 周期最多一个哨兵（`_sentinel_pending`，线程取出后清零，新周期
  可再插）；
- `statistics()["queued"]` 扣除未消费的哨兵（不含控制哨兵）；
- 线程退出后 `put_job` 抛 `RuntimeError`（受控异常，任务不滞留队列）；
- 多次 stop 不改变已归零统计。

**测试**（`DecoderStopIdempotencyTests`）：
- `test_stop_three_times_queued_zero`（3 次 stop 均 True、queued==0）
- `test_put_job_rejected_after_exit`（退出后 put_job RuntimeError）
- `test_statistics_no_control_sentinel`（queued 不含哨兵、decoded_success 正确）

### 三、closeEvent 对 Qt 待处理回调的判断

**修改**（`uav_gpr_ground_station.py`）：
- ReceiverThread 新增 `emitted_pending()`（emit 前 `_note_emitted`；主线程槽
  `_on_receiver_trace_received` 的 finally 中 `note_signal_consumed`）；
- closeEvent 屏障链：receiver stop+wait → **emitted_pending==0** → decoder
  drain+stop（检查返回值）→ **decoder in_callback==0** → display FIFO depth==0
  且 unresolved==0 → accept。任一非零 → ignore（不清队列、不丢回调、不
  terminate）；排空后再次关闭成功。

**真实竞态测试**（`TwoPhaseCloseTests`）：
- `test_close_race_with_pending_callbacks`：提交 decoder 任务 → 立即
  closeEvent（不处理事件）→ 第一次 **ignore** → processEvents 直到完成
  B-scan 提交 → 第二次 **accept** → 无 receiver/decoder 线程残留、
  in_callback==0、depth==0、unresolved==0。
- `test_display_fifo_real_trace_close_twice`：旧测试未加真实 Trace——已修正为
  向 FIFO 加入**有效 DecodedGroundTrace**：第一次 close ignore → 提交显示
  （committed==1）→ 第二次 accept。

### 四、displayed/committed 计数语义

**根因**：`GroundDisplayFIFO.pop()` 直接 +total_committed——pop 只是出队。

**修改**（GroundDisplayFIFO + `_process_one_display_item`）：
- 独立统计：`total_enqueued / total_dequeued / total_committed /
  total_rejected / total_failed / unresolved`。
- `pop/popleft` 只计 dequeued；只有 校验通过→原子追加成功→refresh/setImage
  成功→当前 Trace 状态提交成功 全部完成后才 `mark_committed()`；
- 时间轴/Dewow/无效 Trace → `mark_rejected()`（不增 committed）；
- setImage/UI 提交异常 → `mark_failed()`（不增 committed，异常明确记录）；
- 停止屏障与 closeEvent 使用 committed/rejected/failed；
- 全链路基准 `displayed` 读取 `total_committed`（不再把 pop 数当 displayed）。

**测试**：
- `test_statistics_and_clear` / `test_mark_rejected_and_failed_not_committed`
  （FIFO 计数语义）；
- `test_rejected_trace_no_display_count`（**修正反向断言**：拒绝前后
  committed 不变、rejected +1、dequeued +1、unresolved==0、历史与当前
  Trace 标签保持上一条成功状态）。

### 五、failed_item 最终状态

**根因**：put 超时产生 failed_item 后，consumer 排空其余队列得到 drained，
worker 仍发 stopped/drained。

**修改**（`uav_gpr_qt.py` ContinuousAcquisitionWorker）：
- 新增 `_terminal_error` / `terminal_state`；
- finally 综合 5 项判定：`processing_queue.failed_item`（含 trace_index 与
  原因）、worker terminal error、consumer.drain_state、consumer.drain_failures、
  selected/processed 对账——任一非空 → `terminal_state="failed"` + failed.emit
  汇总 + 最终状态消息 `state="drain_failed"`（**绝不** stopped+drained）；
- 成功任务仍要求 selected==processed==saved 才发 `stopped`+`drained`。

**worker 级测试**（`WorkerTerminalStateTests::test_failed_item_yields_drain_failed_status`）：
真实 fake 设备 worker 全链 + 容量1 队列 + 首条处理延迟 0.6s 的阻塞 consumer +
注入 0.3s put 超时 → 捕获 `RemoteSender.enqueue_status` → 断言最终
`state=="drain_failed"`、无 stopped、无 drained、`_terminal_error` 含
`trace #2`（失败 Trace 编号）。
