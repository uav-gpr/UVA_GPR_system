## 二、关键背景：空中端将运行在"计算棒"上

**约束**：计算棒（stick PC）通常没有显示器和键鼠；飞行时更不可能有人在旁边点界面。

**现状核查（已读代码，均为事实）**：

| 项 | 现状 | 影响 |
|---|---|---|
| 配置持久化 | **完全没有**（无 QSettings、无 JSON 配置文件） | 每次开机都要人手设置 GNSS 口 / 地面站 IP / 引擎 |
| 命令行参数 | **没有**（`QApplication(sys.argv)` 直接起窗口） | 无法用参数指定连哪个地面站、用哪个串口 |
| GNSS 串口 | 人手点"刷新"再下拉选，且代码硬编码优先 `COM3` | 棒子无界面 → 无法选择 |
| 地面站地址 | 默认 `127.0.0.1`，要人手填并点 Connect | 棒子无人操作 → 永远连不上 |
| 唯一入口 | 只有 GUI | 没有人机之外的配置途径 |

**结论**：棒子要在空中跑起来，必须新增"无人值守"能力；地面端必须能**全远程**管理与诊断。

## 三、方案（三层，按必要性排序）

### 第 1 层：无人值守基础（**必需**，否则棒子跑不起来）

1. **配置文件**：新增 `air_config.json`（GNSS 串口 / 地面站 IP 与端口 / 采集引擎 / 输出目录 / 是否开机自动采集），空中端启动即读取并应用。
2. **命令行参数**（可覆盖配置文件，便于地面调试）：`--config <路径>`、`--server <ip:port>`、`--gnss-port COMx`、`--engine continuous|legacy`、`--autostart`。
3. **GNSS 串口自动探测**：启动时扫描全部串口，逐个试读 NMEA，能解析出有效 GGA 的那个即为 GNSS；找不到则状态上报"未找到 GNSS"（地面端可见），并继续重试。
4. **自动连接 + 断线自愈**：启动即按配置连地面站；连不上按退避重试（现有 `RemoteSender` 已有重连逻辑，此处将其自动化）。地面站地址支持配置多个候选，依次尝试。
5. **开机自启**：提供一键安装脚本（Windows 任务计划程序 / 启动文件夹），实现"插电即运行"。

### 第 2 层：地面端全远程（**必需**，Q3 的升级版）

地面端新增「**空中端设备**」面板，全部经既有 `command` 通道**新增 action** 实现（framing 红线：只新增，不改既有字段）：

| 远程能力 | 地面端能看到/做到 |
|---|---|
| 测试雷达 | 点一下，空中端执行并回传**固件 / 协议版本 / 最大频率 / 设备是否在线** |
| GNSS 串口管理 | 远程**拉取串口列表**、远程**选择**串口与波特率、远程**测试 GNSS**（回传是否解析出有效定位、卫星数） |
| 采集引擎 | 远程查看当前引擎、远程切换（高速连续 / 兼容） |
| 设备状态总览 | 服务状态、USB 是否连接、当前 run_id、是否在采集、队列深度（这些已有部分，补齐成"一眼看全"） |
| 采集任务 | 开始 / 单次 / 暂停 / 继续 / 停止（**已实现**） |
| 参数下发 | 扫描与处理参数（**已实现**） |

### 第 3 层：棒子的人机入口（**强烈建议**）

6. **轻量网页配置页**：棒子上跑一个极小的本地网页服务（例如 `http://<棒IP>:8080`），用**手机或笔记本浏览器**就能：
   - 看状态（雷达在不在、GNSS 有没有定位、连没连上地面站、当前引擎、trace 计数）
   - 改配置（串口、地面站 IP、引擎）并保存到配置文件
   - 看最近日志（便于现场排障）
   
   > 意义：彻底解决"棒子接不了屏幕"，且不依赖我们的地面站软件（换台电脑、用手机都能进）。

7. **失联行为**（需 Q6 决策）：地面站断线时，空中端**继续采集并本地保存**（推荐，配合第 2 轮磁盘 outbox，联上后自动补发）还是立即停止。

### 明确不做（避免过度工程）

- 不改 telemetry framing 既有字段/类型（只新增 action 与新消息类型）
- 不做"完全无头"的大改造（见下方风险说明），先用"开机自启 + 配置化 + 网页入口"过渡
- 不做多地面站集群、不做加密鉴权（单机内网场景）

## 四、剩余待确认的选择

### Q4　棒子上的默认行为：开机就自动开始采集？

- **A（推荐）** 开机自动开始采集：飞行时无人操作，且**断网也不丢数据**（本地保存 + 磁盘 outbox 事后补发）
- **B** 开机只待命，等地面端点"开始"：更可控，但若地面站没起来就白飞

### Q5　要不要"手机浏览器配置页"（第 3 层第 6 项）？

- **A（推荐）** 要：棒子接不了屏幕，这是唯一不依赖地面站软件的人机入口
- **B** 不要：只靠地面站远程 + 配置文件（现场临时改配置就得拔卡改文件）

### Q6　地面站失联时，空中端怎么办？

- **A（推荐）** 继续采集 + 本地保存 + 联上后自动补发（数据优先）
- **B** 立即停止采集，等重新连上（行为可控，但失联期间的数据没有）

## 六、风险与诚实说明

1. **"完全无头"改造不小**：当前架构是 GUI 驱动（MainWindow 装配服务/worker/消费者/发送器）。真正去掉窗口需要重构装配链。过渡方案：开机自启 + `QT_QPA_PLATFORM=offscreen`（Qt 无显示运行）或窗口最小化——**先满足"无人值守"，不追求零 GUI**。
2. **计算棒 USB 供电**：LibreVNA 功耗不低，计算棒的 USB 口供电可能不足（经验提示，未实测）——现场若出现设备掉线/识别不到，优先怀疑供电，建议用带外接供电的 USB HUB。
3. **棒子性能**：低功耗设备上 B-scan 绘图与 NPZ 压缩可能吃力。若真机出现卡顿，可优先用 `--engine continuous` + 关闭本地 B-scan 显示（待 Q5 方案落地后可远程控制）。
