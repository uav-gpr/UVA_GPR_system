## 一、为什么是这两块（背景）

空中端最终要装在**计算棒**上（无屏幕、无键鼠、飞行中无人操作）。现状核查（已读代码确认）：

| 项 | 现状 | 后果 |
|---|---|---|
| 配置文件 | **完全没有** | 每次开机都要人重设 GNSS 串口、地面站 IP、引擎 |
| 命令行参数 | **没有**（`QApplication(sys.argv)` 直起窗口，`uav_gpr_qt.py:6273`） | 无法用参数指定连哪台地面站、用哪个串口、是否自动采集 |
| GNSS 串口 | 需人手点"刷新"再下拉选 | 棒子上无法操作 |
| 地面站 IP | 默认空（第 5 轮已修，不再自动连 127）；需人手填 | 无人值守时永远连不上 |
| 开机自启 | 无（只有 `run_air_station.bat` 手动双击） | 断电重启后不会自己起来 |

**已裁定的决策（第 5 轮用户拍板，直接沿用）**
- **Q4**：棒子开机只打开空中端，**等待地面端**来连（不自动开始采集）
- **Q5 = B**：**不做**网页配置页
- **Q6 = A**：地面失联时**继续采集 + 本地保存**，联上后自动补发（第 2 轮磁盘 outbox 已具备此能力）

## 二、第 1 层：让棒子"插电就自己干活"（必需）

### 1.1 配置文件 `air_config.json`
放在程序目录旁，启动即读取并应用。字段（全部带默认值，缺省不报错）：

```json
{
  "ground_host": "192.168.144.10",   // 地面站 IP，空则不自动连
  "ground_port": 8765,
  "gnss_port": "COM5",              // 空 = 自动探测
  "gnss_baud": 115200,
  "engine": "continuous",           // continuous | legacy
  "output_dir": "gpr_runs",
  "device_source": "usb",           // usb | simulated
  "autostart_acquisition": false    // Q4：默认 false（等地面命令）
}
```
- 界面里改过设置后**自动回写**该文件（下次开机保持）
- 配置文件损坏/字段非法 → 用默认值启动并在日志里说明，不崩

### 1.2 命令行参数（便于现场排障时覆盖配置）
`--config <路径>`、`--server <ip[:port]>`、`--gnss-port COMx`、`--gnss-baud N`、`--engine continuous|legacy`、`--autostart`（覆盖配置里的采集自启开关）
优先级：命令行 > 配置文件 > 内置默认。

### 1.3 GNSS 串口自动探测
- 启动时扫描全部串口，逐个试读 NMEA，能解析出有效定位（GGA）的那个即为 GNSS
- 探测有超时上限（不能卡住启动），失败则日志写明"未找到 GNSS"并在状态区显示
- 找到后自动填入串口下拉框，不需要人点"刷新"

### 1.4 自动连接 + 断线自愈
- 配置里有 `ground_host` → 启动后**自动连接**（复用第 5 轮的连接逻辑；空则不连）
- 连不上按退避重试（`RemoteSender` 已有重连逻辑，只需自动化）
- Q6=A：**失联不停采集**，数据先落本地 + 磁盘 outbox，恢复后自动补发

### 1.5 开机自启
- 提供一键脚本 `启用开机自启.bat` / `关闭开机自启.bat`（放到用户的启动文件夹，或注册计划任务）
- 自启参数：`--config <同目录 air_config.json>`（不自动开始采集，符合 Q4）

## 三、第 2 层：地面端全远程（必需）

地面端新增「**空中端设备**」面板，全部经既有 `command` 通道**新增 action** 实现（红线：只新增，不改既有字段/类型）：

| 远程能力 | 地面端能得到什么 | 对应空中端控件（已核实行号） |
|---|---|---|
| 测试雷达 | 固件版本 / 协议号 / 最大频率 / 在线与否 | `test_vna_btn`（uav_gpr_qt.py:4344） |
| GNSS 串口列表 | 远程拉取可用串口清单 | `refresh_btn`（:4338） + `port_combo`（:4335） |
| 选择 GNSS 串口 + 波特率 | 远程设定（回执确认） | `port_combo` / `baud_combo`（:4336） |
| 测试 GNSS | 能否解析定位、卫星数（或错误原因） | `test_gnss_btn`（:4343） |
| 采集引擎切换 | 当前引擎 + 远程切换（高速连续/兼容） | `engine_mode_combo` / `continuous_enabled`（:4485） |
| 设备来源 | USB 真机 / 模拟器切换（可选） | `device_source_combo`（:4367） |
| 设备状态总览 | 服务状态、USB 是否连接、run_id、是否在采集、积压条数（部分已有，补齐成一屏） | 现有状态区字段 |

**实现约束**：所有回程结果走既有消息通道（可新增消息类型，或复用 `command_ack` + 结果字段）；旧版本两端仍须能互操作。
