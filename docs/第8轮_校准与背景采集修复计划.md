## 1. 目标和边界

修复用户现场报告的三个问题：

1. OSL 校准完成并激活后，不能继续进行空采背景参考。
2. 不能从地面端使用已校准好的文件。
3. P1_Open 采错后重采，被空中端拒绝，地面步骤长期显示“请求采集中”。

交付配套的 **Windows x64 地面站便携包、空中黑匣子便携包**，自带原有 Python 和依赖；不要求用户安装开发环境。不改 HM30 地址、采集引擎默认值、既有 GNSS 设置，不增加自动部署，不在本机注册/运行计算棒自启任务。

工作目录：`D:\博士任务\UVA_GPR_system`。当前分支 `my-modifications`，存在用户既有未提交改动和未跟踪文件。必须保留，禁止 reset/checkout/clean、提交、删数据或用 HEAD 覆盖工作区。修改以当前工作区为基础。旧发布包与真实校准文件原件必须保留。

## 2. 已核实的原因

### 2.1 校准后不能采背景：地面向导没有结束已完成的会话

[地面向导控件锁定逻辑](<D:/博士任务/UVA_GPR_system/uav_gpr_ground_station.py#L2347-L2372>) 把 `_cal_id != None` 视为会话仍在进行，因此禁用“开始校准”和模式选择。

[激活回程处理](<D:/博士任务/UVA_GPR_system/uav_gpr_ground_station.py#L2533-L2568>) 收到 `activated` 只修改提示文字，没有解除这个锁定。关闭再打开仍使用同一个向导对象。

无硬件独立验证实际输出：

```text
ACTIVATED UI: session_retained=True mode_enabled=False begin_enabled=False
```

[空中黑匣子的互斥规则](<D:/博士任务/UVA_GPR_system/uav_gpr_air_service.py#L1112-L1140>) 已将 `activated` 排除出“进行中”，所以至少有一处明确的卡点在地面端。若只解算未激活，空中 `solved` 会话仍占用流程，这与“校准已生效”不是一回事，界面应说清楚。

### 2.2 已有校准文件不能使用：远程入口缺失，且读文件有两套规则

[黑匣子命令表](<D:/博士任务/UVA_GPR_system/uav_gpr_air_service.py#L754-L775>) 支持六个 `cal_*` 会话命令，但没有导入/加载已有文件的入口。[初始化](<D:/博士任务/UVA_GPR_system/uav_gpr_air_service.py#L653-L668>) 将外部校准路径置空，[配置字段](<D:/博士任务/UVA_GPR_system/uav_gpr_air_service.py#L97-L114>) 也没有保存已启用校准的引用。

此外，[旧底层读法](<D:/博士任务/UVA_GPR_system/librevna/librevna_usb_s11.py#L75-L111>) 只认 `Open/Short/Load`；[现行格式读法](<D:/博士任务/UVA_GPR_system/calibration_service.py#L187-L245>) 能认 `P1_Open/P2_Open` 等步骤并分别生成两端口校准。

仓库保留的真实 [双端口校准文件](<D:/博士任务/UVA_GPR_system/solt_2port_20260807_202342.json#L1-L21>) 是 `uav_gpr_solt_calibration_v2`。无硬件独立验证：

```text
V2 READER: port 1 points=201
V2 READER: port 2 points=201
LEGACY ONLY READER REJECTS V2:
Calibration file is missing measurements: Open, Short, Load
```

因此不能简单地“把一个路径塞进旧读法”。更不能把地面电脑的路径当作空中电脑也存在的路径。

### 2.3 重采失败：地面退回了，空中没有退回

[地面重采](<D:/博士任务/UVA_GPR_system/uav_gpr_ground_station.py#L2458-L2468>) 将本地步骤索引改回 P1_Open，然后发送普通的 `cal_capture(P1_Open)`。

[空中入口](<D:/博士任务/UVA_GPR_system/uav_gpr_air_service.py#L1248-L1278>) 和 [共享会话状态机](<D:/博士任务/UVA_GPR_system/calibration_service.py#L867-L890>) 都只允许“下一待采步骤”。P1_Open 已完成，空中自然在等 P1_Short。

无硬件独立验证实际输出：

```text
after P1_Open, air next = P1_Short
RECAPTURE REJECTION: 下一待采步骤为 P1_Short，收到 'P1_Open'
REJECTED GROUND ROW: 请求重采中… ground next = P1_Open
```

[拒绝处理](<D:/博士任务/UVA_GPR_system/uav_gpr_ground_station.py#L2561-L2568>) 只改总提示和 `_capturing`，没有修正表格文字及下一步索引。这就形成了截图中的“按钮能点，但每次都送错步骤”。

空中日志中的 `SET_IDLE`/USB 待命是已完成步骤的正常收尾；截图中这次重采在步骤检查时已经被拒绝，不能靠反复点按钮解决。以上不等于已验证真实 USB/标准件测量质量。

### 2.4 为什么旧测试没挡住

[既有向导重采测试](<D:/博士任务/UVA_GPR_system/tests/test_ui3_calibration_wizard.py#L248-L285>) 用假的接收器，并人工注入“重采成功”，未把命令交给真实空中入口。因此单测中的地面成功与现场空中拒绝可以同时存在。本轮必须补真实双端命令往返验证，不能继续用“自己宣布成功”的测试证明修复。

### 2.5 发布版本对应关系

已用 SHA-256 对照当前源文件与现有便携目录：地面主程序、空中黑匣子主程序、共享采集核心、共享校准服务均一致。现场照片目录标有 20261012；照片不能证明那台机器每个文件的具体哈希，但此次诊断针对的是本地最新打包源码，而非旧 HEAD。

## 3. 预期修改

### A. 把“正在做校准”和“已经启用的校准”分开

- 地面收到可信的激活成功回执后结束操作会话，恢复模式选择和开始按钮；保留生效摘要，不清掉实际 OSL。
- 用户接着选“空采参考（背景）”即可新建背景会话，无需重启两端。
- 建立、拒绝、失败、取消、关闭/重开、断线/重连都应有明确状态；创建会话失败不能永久占住按钮。
- 查询生效状态时，展示真正生效的 OSL 与背景信息，不把“当前正在操作的会话”当作唯一的生效记录。
- OSL 后背景仍在当前 OSL 校正域中使用，保持 P1/P2 校准独立。当前背景功能按既有 S11 范围工作，不擅自广播给 S22。
- 切换 OSL 时对旧校正域背景显式失效/清除并提醒，防止“看似启用、数值却混用了两套校准”。

### B. 补齐从地面选文件到空中实际启用的整条路

- 地面增加“加载已有校准”入口，显示文件名、可用端口、频段和生效状态；必要时提供“保存/导出当前 OSL 校准”方便跨次复用。
- 通过既有 `type=command` 的动作和参数发送文件内容（不是仅发送地面路径）；校验大小、结构、数值有限性、标准件完整性、每步频率轴和可用频带。
- 复用现有 v2 文件格式；兼容旧 `Open/Short/Load` 文件。双端口文件必须独立恢复 P1/S11、P2/S22 和已有 Through 能力；单端口文件明确显示范围，不能伪装成双端口。
- 空中先验证、再原子落盘、再启用；失败保留上一套可用校准，回执解释原因。
- 已启用 OSL 的持久化引用随配置保存，空中重启从持久化文件恢复；文件不存在/损坏要明确报警，不显示虚假的“已启用”。旧配置缺新字段仍能启动。
- 保存/导出结果应是完整可重读的校准内容，不能只把空中电脑路径显示给地面用户。
- 频带外不得静默外推；不兼容采集参数明确提示。旧软件对新增能力回“不支持/需要配套升级”，不崩、不假成功。

### C. 真正支持重采，并让地面跟随空中确认

- 建议保留 `cal_capture` 动作，加显式 `recapture` 标志；最终字段、请求关联和回执规则由需求任务一次性定稿，两位工程师共同读取，不能各自猜。
- 空中共享会话层实现选择步骤重采：只替换所选步骤的数据，保留其他已完成步骤；从当前第一项未完成步骤继续，不要求用户把所有步骤重做。
- 保存各次原始采样的审计证据，重采不能悄悄覆盖唯一原始文件；计数与均值只能使用当前成功那次数据。
- 重采后旧解算/质量结果作废，全部当前数据有效后才可重新解算/激活。已激活校准不能被后台重采悄悄修改。
- “重采该步骤”点击一次直接重采，不要求随后再点“采集下一步”；请求处理中禁重复发起，重复请求可识别。
- 地面按步骤完成集合计算进度；拒绝/失败时对应行变为可解释的状态并恢复正确下一步，不保留“请求采集中”的假状态。
- 最后一条样本到达不等于空中状态及 worker 已完全收尾；需要真实步骤完成/可继续回执后再放开下一步和解算，处理收尾竞态。
- 超时、断线、迟到旧回执有边界；先查状态再恢复，不无条件重复发采集造成多次执行。请求关联和会话身份隔离要覆盖旧包回执。

## 4. 不可破坏的既有行为

1. 地面到空中不新增消息 `type`；只能扩展既有 `command` 动作/参数，保持 framing 不变。
2. 常驻 USB 服务是硬件唯一入口；校准/背景不自开自关抢 USB。采集与校准互斥、排空与待命行为保留。
3. run_id 轮换、带内 hello、trace 去重与 ACK、断链 outbox 补传、接收端 fail-closed 行为不得被顺手修改。
4. 旧 GUI 空中端和新黑匣子端尽量复用校准数据逻辑；新增能力对旧端清楚说明支持情况，不能让正常旧流程永久等待新回执。
5. 实部显示、现有滤波/时域算法、道率与 GNSS 代码非本轮目标。
6. 禁止删旧测试凑全绿。旧测试若表达了错误的产品语义，可按新需求修正断言并逐项解释；必须增加真的两端连起来的回归。
