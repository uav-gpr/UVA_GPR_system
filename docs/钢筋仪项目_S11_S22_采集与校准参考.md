# 钢筋仪项目 S11/S22 采集、处理与校准参考

## 1. 结论

对 `E:\钢筋仪软件开发` 只读分析后，最值得当前 UAV-GPR 项目借鉴的是两点：

1. **采集必须采用持久 USB 会话。** USB 只打开一次，扫频参数只配置一次，之后从 LibreVNA 连续输出流中逐道取得完整 sweep；停止时才 `SET_IDLE` 并释放 USB。
2. **S11 与 S22 是两个独立的一端口反射通道。** 每个频点从同一个 VNADatapoint 中解出 S11/S22；校准时分别建立 P1-S11 和 P2-S22 的三项 OSL 模型，绝不能共用一套误差项。

当前项目的 `librevna/librevna_usb_s11.py::acquire_sparameters()` 每调用一次都会执行 `open_device → RequestDeviceInfo → SET_IDLE → SWEEP_SETTINGS → 采一条 → SET_IDLE → release_interface`。连续采集、每个校准标准件重复采集时，这些握手和 USB 重建会被重复执行，是明显的软件开销。它还以字典按 `point_number` 覆盖和排序，只检查最终数量，没有像参考项目那样严格保证一条数据一定来自连续的 `0..N-1`，因此发生丢包、重复点或跨 sweep 时更难发现数据污染。

## 3. S11/S22 数据采集流程

### 3.1 会话生命周期

参考项目的生命周期为：

```text
open
  └─ USB open（一次）→ RequestDeviceInfo → SET_IDLE
configure
  └─ 校验参数 → SET_IDLE → 清旧流 → SWEEP_SETTINGS 0x1241（一次）
acquire_one × N
  └─ 从连续 VNADatapoint 流取下一条完整 sweep；不重新配置、不 sleep
close
  └─ SET_IDLE → release_interface / dispose_resources
```

双反射通道使用 `stages_bitmap = 0x1241`：

- channel 0 = `HH:S11`，stage 0；
- channel 1 = `VV:S22`，stage 1。

每次 USB read 使用短超时（参考项目默认 50 ms）只是为了能及时响应停止，不代表一条 sweep 的总超时。总超时按下面的保守估计自动给出：

```text
expected ≈ n_points × n_stages / IFBW
sweep_timeout = max(2 s, expected × 5)
```

双通道有两个激励 stage，所以估算中的 `n_stages=2`。

### 3.2 一个频点如何得到 S11 与 S22

一个 VNADatapoint 内含若干 `(descriptor, complex receiver)`。descriptor 的关键位为：

- `stage = descriptor >> 5`；
- bit 4 表示 reference；
- bit 0 表示 Port1 receiver；
- bit 1 表示 Port2 receiver。

同一个包内计算：

```text
S11 = stage0 的 Port1 receiver / stage0 reference
S22 = stage1 的 Port2 receiver / stage1 reference
```

真实 protocol 14 双阶段包中常见 descriptor 为 `01 02 13 21 22 33`。其中 stage0-Port2 和 stage1-Port1 对本双反射任务不是必需输入。参考项目只要求构造 S11/S22 所需的四项各出现一次；缺失、重复、reference 为 0、NaN/Inf 时，整个频点无效，继而丢弃整条 sweep。它不会把两个包中的“半个频点”拼起来。

当前项目的 `datapoint_to_sparameters()` 会生成 S11/S21/S12/S22，`acquire_sparameters()` 又要求四项全有才接受频点。若当前任务只使用反射 S11/S22，应改成明确的双反射解析路径；不应让一个不使用的传输项缺失导致整个频点被拒绝。

### 3.3 完整 sweep 状态机

连续 USB 数据没有可靠的 sweep ID，因此参考项目采用保守策略：宁可丢一条，也不把两条拼成一条。

- 只有 `point_number == 0` 可以开始新 sweep；
- 后续必须严格为 `1, 2, ..., N-1`；
- 跳号、回退、重复、越界、无效复数会立即废弃当前 sweep；
- 失步后忽略所有非 0 点，直到下一个 point 0；
- 完成时还要检查设备实际返回的频率有限且严格递增；
- 同一次 USB read 中属于下一条 sweep 的包进入 pending 队列，不能丢掉；
- 输出使用设备实际频率，不用 `linspace(start, stop, points)` 替代。

建议长期记录这些诊断计数：`dropped_sweeps`、`incomplete_sweeps`、`duplicate_points`、`out_of_range_points`、`invalid_points`。当图像质量突然变差时，这些计数比单纯看 GUI 更容易区分“射频噪声”与“数据流损坏”。

### 3.4 参考项目的真机速度基线

外部项目记录的 LibreVNA 真机结果（0.5–2.5 GHz、101 点、IFBW 10 kHz、固件 1.6.5/protocol 14）为：

- 单 S11：平均约 23.969 ms/道，约 41.72 道/秒；
- 双反射 S11+S22：平均约 39.92 ms/道，约 25.05 道/秒。

这说明双通道本身会因两个 stage 变慢，不能直接期待单通道速度；但每条都重新打开/配置 USB 仍然是不必要的额外损耗。参考项目还特别说明，按 `points/IFBW` 推算出的 90–99 道/秒不符合该参数下的真机结果，优化时应以实测墙钟时间为准。

## 4. 双反射六步校准流程

### 4.1 物理连接顺序

这不是完整的二端口 SOLT，也没有 Through。它只校准 S11 和 S22：

1. P1 接 Open，P2 接匹配负载；采 S11；
2. P1 接 Short，P2 接匹配负载；采 S11；
3. P1 接 Load，P2 接匹配负载；采 S11；
4. P2 接 Open，P1 接匹配负载；采 S22；
5. P2 接 Short，P1 接匹配负载；采 S22；
6. P2 接 Load，P1 接匹配负载；采 S22。

“另一个端口接匹配负载”是物理前提，软件无法验证。若另一个端口悬空，端口耦合和多次反射会进入标准件测量，后续数学再正确也无法得到可信校准。

### 4.2 重复采集与复数平均

每一步采多条完整 sweep，再对复数值直接平均：

```python
standard_mean = np.mean(captures_complex, axis=0)
```

外部 UI 默认每个标准件 16 条，可调范围 1–256；双通道六步、16 条/步意味着总计 96 条 sweep。复数平均可以降低不相关随机噪声，但前提是线缆、标准件和相位在采集期间稳定。不能先分别平均 dB 和角度。

### 4.3 三项误差模型

P1 和 P2 分别求解三项误差：

- `D`：directivity（方向性）；
- `T`：reflection tracking（反射跟踪）；
- `M`：source match（源匹配）。

对原始测量值 `m`，校正后的真实反射系数为：

```text
x = m - D
Γ = x / (T + M×x)
```

Open、Short、Load 的理想值默认分别为 `+1`、`-1`、`0`，也可以提供随频率变化的标准件模型。`reference_code/rebar_inspector_s11_s22_reference.py` 中的 `_solve_osl()` 保留了外部项目同构的求解公式，并检测过小分母。

最终组合关系必须固定：

```text
raw[..., 0, :] --S11 profile(D11,T11,M11)--> calibrated[..., 0, :]
raw[..., 1, :] --S22 profile(D22,T22,M22)--> calibrated[..., 1, :]
```

两套 D/T/M 不得交换或共用。两个子 profile 的频率轴必须逐元素完全一致；应用时允许在校准带内对实部、虚部分别线性插值，但禁止频带外外推。

### 4.4 校准质量检查

外部项目同时记录两类误差：

- 用平均标准件反算的最大绝对误差，检查 OSL 拟合自洽性；
- 对每条重复 capture 校正后的 RMS/最大绝对误差，检查重复性。

拟合误差很小只说明三项模型能拟合这三组平均值，不等于现场校准一定正确。还应检查：

- Open/Short/Load 是否接对、是否压紧；
- 另一端口是否确实匹配终端；
- 校准后 Load 是否接近 0，Open/Short 是否接近 ±1；
- 校准与测量的频段、点数、IFBW、功率、线缆和连接方式是否一致；
- 两次采集之间是否移动了参考面或弯折了线缆；
- S11 与 S22 的重复误差是否分别稳定。

## 5. 频域到 B-scan 的处理顺序

外部项目的数据约定为：单条数据 `(channel, frequency)`，B-scan 为 `(trace, channel, frequency)`，全程保存 `complex128`。处理顺序为：

```text
frequency_raw
  → 可选：双通道独立 OSL
  → 可选：空采背景
  → 可选：带通/窗函数
  → 补零 IFFT
  → time_base
  → 可选：Dewow（沿时间轴）
  → 可选：Flat Reflection（沿 trace 轴）
  → time_processed
```

关键约束：

- 原始复数频域数据永不就地覆盖，应分别保留 raw、calibrated、time_base、time_processed；
- OSL 必须在背景扣除、带通和 IFFT 之前；
- 已校准数据必须带 profile 身份和通道顺序，防止二次校准；
- 外部项目目前**没有实现双通道空采背景**，会明确拒绝，而不是把单通道背景广播到 S11/S22；当前项目若实现，背景必须也是完全匹配的 `(2, frequency)`，并且与待减数据处在同一 RAW/OSL 域；
- Dewow 是沿时间轴减中心移动平均；Flat Reflection 是沿测线方向减局部均值，可能同时削弱真实水平层状目标；
- OSL 后峰位变化不等于已经完成 time-zero 校正，两者是不同问题。

## 6. 对当前 UAV-GPR 项目的改造建议

建议按以下顺序实施，便于逐步验证：

1. **先只改生命周期。** 保留当前 `PacketStream`、包编码和 USB transport，把设备对象提升为采集线程整个生命周期持有；开始采集时 open/configure 一次，循环中只调用 `acquire_one()`，停止时 close。
2. **引入严格 assembler。** 不再用字典覆盖点号；任何跳号/重复/无效点丢整条，并把统计显示在日志或状态栏。
3. **拆出双反射解析器。** 每包只要求 S11/S22 所需输入，同包计算两通道，固定输出顺序 `(S11,S22)`。
4. **先做吞吐基线。** 关闭绘图和存盘各测一次，再打开存盘、最后打开 GUI 刷新；分别记录设备 sweep 时间、解析时间、保存时间和 UI 时间，避免把显示卡顿误判成设备慢。
5. **接入六步双 OSL。** 每步默认 16 条复数平均；保存两套 profile、频率轴、采集配置、重复性指标和时间戳。
6. **最后调成像参数。** 确认 raw 流和 OSL 正确后，再调整带通、时窗、Dewow 和背景，否则后处理可能暂时“看起来更干净”，却掩盖底层丢点或校准错误。

速度与质量参数存在真实权衡：提高 IFBW、减少频点可提速但通常增加噪声或降低距离分辨能力；降低 IFBW、增加 dwell 会改善稳定性但更慢。校准标准件可以多次平均，因为它们静止；移动测量时不应盲目跨多条 trace 平均，否则会把空间目标抹宽。

## 7. 参考代码最小用法

构建双反射 OSL：

```python
from reference_code.rebar_inspector_s11_s22_reference import build_dual_reflection_osl

profile = build_dual_reflection_osl(
    frequency_hz,
    p1_open_s11=p1_open[:, 0, :],
    p1_short_s11=p1_short[:, 0, :],
    p1_load_s11=p1_load[:, 0, :],
    p2_open_s22=p2_open[:, 1, :],
    p2_short_s22=p2_short[:, 1, :],
    p2_load_s22=p2_load[:, 1, :],
)

# raw_bscan: (trace, 2, frequency)
calibrated_bscan = profile.correct(frequency_hz, raw_bscan)
```

连续采集骨架：

```python
config = SweepConfig(500_000_000, 2_500_000_000, 101, 10_000)
session = PersistentDualReflectionAcquirer(your_transport_adapter)
session.open()
try:
    session.configure(config)       # 只执行一次 SWEEP_SETTINGS
    while collecting:
        sweep = session.acquire_one()  # 不 reopen/reconfigure/sleep
        save_or_emit(sweep)
finally:
    session.close()
```

`your_transport_adapter` 需要把当前项目的 PyUSB/packet 代码封装成 `open()`、`set_idle()`、`start_continuous()`、`read_events()`、`close()`。等待命令 ACK 时同时到达的数据包必须缓存，不能丢弃。

## 8. 使用边界

这份 Python 文件是可运行、可测试的架构和数学参考，不是已经接好当前硬件的替换后端。外部项目文档显示连续双通道协议解析已做 protocol 14 真机抓包验证；但其六步双端口物理 OSL 流程仍标注为需要现场硬件最终验收。因此接入当前项目后仍必须用真实 Open/Short/Load、匹配终端和已知负载完成验收，不能只凭合成单元测试宣称校准质量合格。
