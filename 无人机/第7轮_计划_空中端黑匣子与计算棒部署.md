# 第 7 轮 计划：空中端黑匣子化（去 UI）+ 地面端全遥控 + 计算棒部署

日期：2026-09-30　状态：**待用户审核 → 审核通过后组队执行**（组队由用户在 Web 面板指派每个角色的模型并点启动）

---

## 一、一句话目标（比喻版）

把空中端从"一台带屏幕按钮的电脑"变成**机顶盒式的黑匣子**：

- **插电就干活**：计算棒通电 → 程序自己启动 → 按提前写好的地址自动去找地面端（连不上隔几秒再试，中途断线也自动重连，永不放弃）；
- **一切听遥控器**：所有原来要在空中端界面上点的操作，全部搬进地面端界面，隔空遥控；
- **活儿还在黑匣子里干**：控制雷达、采数据、发数据、失联补传这套核心逻辑仍在空中端后台跑（雷达插在棒子上，物理上搬不走），只是从此没有窗口。

---

## 二、与第 6 轮计划的关系

第 6 轮计划（`docs/第6轮_计划_无人值守与全远程.md`，9 月 26 日）的目标相同，但当时方案是**保留空中端界面**、只加配置文件和自动连接。本轮用户拍板**更彻底**：空中端 UI 全去掉、新做一个专用小后台程序。因此：

- 第 6 轮"作废"：其第 1 层（配置文件、命令行参数、自动连接、开机自启）的**需求被吸收**进黑匣子设计，但落点从"大 GUI 程序"改为"新后台程序"；
- 第 6 轮第 2 层（地面端全远程面板）**直接沿用并扩大**：用户已把五项能力全部点上；
- 第 6 轮 1.3"GNSS 开机盲扫自动探测"**改为**"地面端远程列串口/选串口"（当前没有 GNSS 硬件，将来插上后在面板上选一下即可，不做开机盲扫）。

## 四、黑匣子（空中端）设计

### 4.1 新程序与复用零件（已核实：以下类/模块均在仓库现有代码中）

新入口程序暂名 `uav_gpr_air_service.py`：启动后无任何窗口，只在后台跑，日志写本地文件。

| 现成零件 | 所在位置 | 在黑匣子里的用途 |
|---|---|---|
| `AcquisitionService` | `uav_gpr_qt.py:2839` | 采集总调度（状态机、命令响应、run_id 管理） |
| `ContinuousAcquisitionWorker` | `uav_gpr_qt.py:3473` | 高速连续采集引擎 |
| `RemoteSender` | `uav_gpr_qt.py:1344` | 向地面端发数据（第 6 轮文档核实其已有重连逻辑） |
| `GnssReader` | `uav_gpr_qt.py:872` | GNSS 串口读取（现在没硬件，配置空=不启动） |
| 校准采集（`ServiceStepCapturer` 等） | `uav_gpr_qt.py:2605` | 支持地面端校准向导远程指挥 |
| `FixedIntervalSweepSelector` | `acquisition_scheduler.py` | 道率限流（已知链路 7.7Mbps，沿用现有默认） |
| `DiskOutbox` | `disk_outbox.py` | 失联补传队列 |
| 便携包结构 | `dist/空中端便携包/` | 新黑匣子便携包照此结构重打 |

**复用方式**：黑匣子程序直接 import `uav_gpr_qt.py` 里的现有类（该文件只有直接运行才会弹窗，import 不会），**单一事实来源，杜绝"抄一份改出两套行为"**。黑匣子用 `QCoreApplication`（无界面内核）+ offscreen 模式跑这些零件。

> 务实说明：因为共用核心代码，黑匣子便携包**体积不会明显变小**（省掉的主要是不弹窗、不需要人操作）；真正把核心抽成"无 Qt 纯净版"属于大手术，本轮不做（见"非目标"）。

### 4.2 配置文件 `air_config.json`（放程序目录旁，开机即读）

```json
{
  "ground_host": "192.168.144.20",
  "ground_port": 8765,
  "gnss_port": "",              // 空 = 不用 GNSS（现状默认，与 2026-09-30 的改动一致）
  "gnss_baud": 115200,
  "engine": "continuous",       // continuous | legacy
  "device_source": "usb",       // usb | simulated
  "output_dir": "gpr_runs",
  "autostart_acquisition": false,   // D11：等地面命令
  "disk_min_free_gb": 20,       // D10：磁盘触发线（按 256G 盘设定）
  "disk_target_free_gb": 40     // D10：清理目标线（清回剩余 ≥40GB）
}
```

- 配置损坏/字段非法 → 用默认值启动并在日志里说明，不崩；
- 地面端远程改的设置（如 GNSS 串口、引擎）**自动回写**该文件，下次开机保持。

### 4.3 自动连接与断线自愈（D3）

启动 → 读配置 → 连 192.168.144.20:8765（地面端先开机晚开机都行，黑匣子一直等）；连不上按退避重试（5 秒起步，最长 30 秒一次，详见默认参数表）；中途断线自动重连；全部复用第 2 轮既有的失联补传（数据不丢，恢复后自动补发，积压条数上报地面端）。

### 4.4 磁盘水位自动清理（D10）

- 定期检查数据盘剩余空间，低于触发线（默认 20GB）时**从最老的 run 开始删**，删回目标线（默认 40GB）为止；
- 优先删"已成功发给地面端"的旧数据；极端情况（盘上全是未送达数据且已满）才动未送达数据，此时**必须**在日志和地面端面板上显式报警"有数据因磁盘满被清理"，绝不静默；
- 删除动作逐条记账进日志（沿用项目"透明记账、零静默"的铁律）。

### 4.5 日志（D9）

- 本地滚动日志文件（默认单文件 20MB、保留 10 份，防写满硬盘）；
- 关键状态（连接状态、VNA 在线、run_id、是否在采、积压、磁盘剩余、程序版本、当前配置）实时上报，在地面端面板显示。

### 4.6 硬约束（红线，沿用项目既有铁律）

1. **严禁地面→空中新增消息类型（type）**——接收端对未知 type 会直接断链（`_wait_for_trace_ack` 对未知类型抛 `ConnectionError`）。所有新远程能力一律走既有 `command` 消息**新增 action 值**，回执走既有 ack 通道 + 结果字段；
2. framing 既有字段**零改动**；只显示实部（禁 abs 控件）；
3. 禁 git 写操作；
4. 测试透明记账（0 静默删除）；全量回归用 `& .venv312\Scripts\python.exe docs\run_tests_batched.py`，判绿以输出 `^OK` 文本为准（基线口径：1007 tests / 35 modules OVERALL OK，见第 6 轮文档记载）；
5. 新旧两端必须互操作：**老空中端**收到新 action 应回"此功能不支持"而不是崩；**新黑匣子**收到老地面端指令照常工作。地面端面板对"不支持"要有明确显示。

## 五、地面端「空中端设备」面板（D1 + D5）

在地面端主界面新增一个面板（不推翻现有布局），五项能力全部经 command 通道新增 action 实现：

| 远程能力 | 地面端能得到什么 |

| 模拟器切换 | USB 真机 / 模拟器（调 bug 用） |

设置类操作（选串口、切引擎、切模拟器）在黑匣子端**回写配置文件**，重启后保持。

## 六、计算棒部署、自启与升级

### 6.1 一次性安装（棒子接一次屏幕键盘，之后再也不用）

1. 把"黑匣子便携包"整个文件夹拷到棒子（U 盘或网线直连拷贝）；
2. 双击 `安装到计算棒.bat`：注册 Windows 计划任务（开机+登录双触发——棒子无开机密码、开机即自动进桌面；开机延迟 30 秒启动、程序崩溃 60 秒内自动拉起、断电重启后自动恢复连接）、生成日志目录；
3. 检查棒子网卡静态 IP = 192.168.144.21（脚本检测并提示，不对则给出改法）；
4. 插上 LibreVNA，按指引确认驱动正常；
5. 拔掉屏幕键盘，棒子只留电源 + 网线（接 HM30 空中端）。

日常使用：棒子通电 → 地面端开软件 → 设备面板看到"在线" → 点"测试雷达"确认 → 点"开始"采集。

### 6.2 升级（D8：手动拷贝）

棒子上跑 `升级_替换程序.bat`（自动：停任务 → 备份旧程序文件夹 → 换新文件 → 重启任务）；或直接 U 盘拷新文件夹替换。地面端面板显示黑匣子程序版本，一眼看出棒子上跑的是哪版。

## 十、非目标（本轮明确不做）

1. **不删**现有空中端 GUI 程序（留在开发机上做调试对照，与黑匣子共用同一套核心代码）；
2. 不做网页配置页（D13）；
3. 不做"地面端主动连空中端"（方向反转，架构大改）；
4. 不做地面端一键推送升级（D8：先手动拷贝，以后想要再加）；
5. 不把核心代码抽成"无 Qt 纯净版"（大手术、回归风险高，收益主要是包体积，不值得）；
6. 不改采集协议、framing 字段、道率限流默认值（吞吐瓶颈是链路物理限制，另行处理）；
7. 不做 GNSS 开机盲扫探测（改为地面端远程选串口）。

## 十一、已补充信息（2026-09-30 用户确认）

1. 计算棒硬盘 **256G** → 磁盘水位按 256G 设定（剩余 <20GB 触发清理、清回 ≥40GB）；按 5 道/s ≈ 1.4GB/小时的数据量，256G 足够存 150+ 小时采集数据，水位清理纯属性能保险；
2. 棒子 Windows **无开机密码** → 开机即自动进桌面，自启任务按"开机 + 登录"双触发注册（当前用户身份运行，USB/串口权限最干净），无需任何额外配置。
